### Violations by feature

**clipboard**
- M features/clipboard/popover.js:62 search `St.Entry` has `hint_text` but no `accessible_name`. Fix: add `accessible_name: _('Search')`.
- M features/clipboard/popover.js:99 Recording toggle is a St.Button wrapping `PopupMenu.Switch`, with no `toggle_mode`, no `checked`, and no toggle role. Fix: `toggle_mode: true, checked: ctl.recording, accessible_role: Atk.Role.TOGGLE_BUTTON`, and sync `checked` in `_syncRecording`.
- M features/clipboard/quickPaste.js:61 search `St.Entry` has no `accessible_name`. Fix: `accessible_name: _('Search Clipboard')`.
- L features/clipboard/popover.js:76 filter buttons use `toggle_mode` but no TOGGLE role. Fix: `accessible_role: Atk.Role.TOGGLE_BUTTON`.
- Note (not counted): features/clipboard/view.js:94 and :144 rows nest Pin and Remove `St.Button`s inside a focusable row button. Keyboard focus lands in both. Consider a `popup-menu` or Shift+Delete shortcut instead of nested buttons.

**controlCenter**
- L features/controlCenter/nowPlaying.js:104 `this._next.reactive = ...` disables the button, but `can_focus` stays true (line 57). Fix: set `can_focus` with `reactive` in the same setter.
- L features/controlCenter/nowPlaying.js:45 and :47 the play/pause name is fixed "Play or pause" and does not say the state. Fix: rename to "Pause" / "Play" per `playing`, as notch does.
- L features/controlCenter/userRow.js:53 `_cluster` gets `accessible_name` but is not focusable and has no role. Fix: give it `accessible_role: Atk.Role.LABEL`, or drop the name if it is decoration.
- Pass: features/controlCenter/tiles.js:41-46 (name, TOGGLE role, can_focus).

**dock**
- M features/dock/stack.js:289 file buttons handle the secondary click only (`clicked` with BUTTON_SECONDARY). They have no `popup-menu` handler, so keyboard users cannot open the file menu. Fix: `button.connect('popup-menu', () => this._host.openFileMenu(button, f, this._stack));` (the same pattern as dock/items.js:52).
- L features/dock/stack.js:209 `StackPopup` root `St.Widget` is reactive and focusable with no name and no role. Fix: `accessible_name: _('Downloads')` (or the stack label) and `accessible_role: Atk.Role.DIALOG`.
- L features/dock/view.js:91 `this.pill` is a reactive `St.BoxLayout` that holds the dock items, with no name and no role. Fix: `accessible_role: Atk.Role.TOOL_BAR` and a name ("Dock").
- Pass: features/dock/items.js:31-35 (name, can_focus, clicked, popup-menu).

**menuBar**
- M features/menuBar/appMenuBar.js:121 Help search `St.Entry` has `hint_text` only. Fix: `accessible_name: hint`.
- L features/menuBar/appMenuBar.js:95-109 `KiwiTopMenu` name comes from `PanelMenu.Button` `nameText`, then `setTitle` updates it. Verify in gnome-shell 50 `panelMenu.js` that the base class sets the accessible name. If it does not, add `this.accessible_name = title` in `_init`.
- L features/menuBar/forceQuit.js:187-189 row buttons are named by app name only. The "(not responding)" state is in a child label and is not announced. Fix: `accessible_name: info.notResponding ? `${info.name}, ${_('not responding')}` : info.name`.
- L features/menuBar/privacyDots.js:72 name "Privacy" is vague. Fix: `_('Privacy indicators')`.
- L features/menuBar/fullscreenReveal.js:71 the reveal edge is reactive with no name. It is a pointer hot zone, not a control. Fix: keep it non-focusable; confirm a keyboard path exists to reveal the menu bar in fullscreen (none found in code).
- Pass: features/menuBar/logoMenu.js:34-40 (name), features/menuBar/aboutDialog.js:76 (label), features/menuBar/forceQuit.js:145 (label), features/showDesktop/index.js:308-335 (name, key handling).

**notch**
- M features/notch/view.js:148 island `St.Widget` is reactive and not focusable, so the notch has no keyboard entry point. Fix: `can_focus: true` on the island (or a keybinding that opens it), plus `accessible_role: Atk.Role.PANEL`. Escape is handled at :263.
- M features/notch/view.js:893-901 seek `St.Button` has `can_focus: false`, so the seek bar is pointer-only. Fix: keep `can_focus: true` and add Left/Right arrow seek on the island while it is focused, or document media keys as the keyboard path.
- L features/notch/view.js:154 `this._island.set_accessible_name?.(...)` uses optional chaining, so the name can be silently skipped. Fix: `accessible_name: gettext('Notch')` in the constructor, the same as the other actors.
- L features/notch/view.js:787-793 action buttons have only a label. Fix: add `accessible_name: action.label`.
- L features/notch/view.js:835-846 Do Not Disturb is `toggle_mode` with no TOGGLE role. Fix: `accessible_role: Atk.Role.TOGGLE_BUTTON`.
- L features/notch/view.js:939-947 media controls: disabled buttons keep their name, and the state is not exposed. Fix: set `reachable`/`can_focus` false when disabled (already done for `can_focus`) and keep names stable.
- Pass: features/notch/view.js:757-764 (Dismiss), :990-995 (recent), :1028-1034 (more), :1047-1055 (clip).

**spotlight**
- M features/spotlight/view.js:169-173 result rows are `St.BoxLayout` with `reactive` and a name, but no role and no focus. Selection moves with the arrow keys in the entry, and assistive tech never hears the active row. Fix: `accessible_role: Atk.Role.LIST_ITEM` (or MENU_ITEM) per row, and a `selected` state; for the entry, update its accessible name or description to the selected row's title on each `_paintSelection`.
- Pass: features/spotlight/view.js:72-74 (entry name).

**stageManager**
- L features/stageManager/strip.js:100 `_root` strip is reactive with no name. Fix: `accessible_name: _('Stage Manager')`, `accessible_role: Atk.Role.PANEL`.
- L features/stageManager/strip.js:365 Shift-click to add to stage reads the pointer modifier (`global.get_pointer`), so the keyboard `clicked` never adds. Fix: provide a keyboard path (for example Shift+Enter via `key-press-event`) and read the modifier from the event.

**windowControls**
- M features/windowControls/index.js:62 `super._init(0.0, 'window-controls', true)` passes the internal id as the panel name. Fix: `super._init(0.0, _('Window Controls'), true)` (the `_` is in scope in `_init`).
- M features/windowControls/index.js:79-82 the three traffic-light `St.Button`s have names but no explicit `can_focus`. Fix: add `can_focus: true` (verify whether St.Button defaults to focusable on GNOME 50; add it explicitly either way).

**lib/modalSurface.js (cross-cutting)**
- M lib/modalSurface.js:112-117 the modal overlay (and the frame at :138) has no accessible name and no dialog role. It is used by spotlight, the dock stack, aboutDialog, forceQuit and quickPaste. Fix: add an `accessibleName` option to `ModalSurface` opts and set `overlay.accessible_role = Atk.Role.DIALOG` and `overlay.accessible_name = opts.accessibleName` in `open()`. Each caller then passes its title.
