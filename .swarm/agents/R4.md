## Findings

### S2-1 Colour filter: wallpaper goes black (alpha 0) after a window animation (the V4 bug is not fixed)
- File: features/colorFilters/index.js:62-100 (per-child effect on Main.uiGroup children), lib/compat.js:149-153 (no paint volume).
- Steps: gs color-filter true (kind greyscale), then Genie-minimize and restore a window (or: SM with many windows, enable the filter). Run C c2: `shots/c2-grey-fresh.png` wallpaper = (53,53,53,255) correct; after `w.minimize(); w.unminimize()` `shots/c2-grey-after-minimize.png` wallpaper = (0,0,0,0) everywhere except a 750x570 rectangle (the window's damage) that is still grey 53. Changing kind (tint) does not repair it. Run B `b7-light-filter.png`, `b7-dark-filter.png`: 353k of 1.02M pixels have alpha 0 (wallpaper black on a real screen; composite on black: scratchpad/r4/onblack-b7-light-filter.png).
- Cause (likely): the effect's offscreen texture is cleared and only the redraw clip is painted into it, so everything outside the damage is empty. Opting out of the paint volume does not widen the clip.
- Fix to try: force a full-stage redraw while the filter is on and window_group is damaged (queue_redraw on `global.stage` from `after-update` when any window actor animates), or give the effect a `vfunc_pre_paint` that resets the clip, or apply the filter to window_group only through `Meta.BackgroundActor`-aware path. Add a regression scenario: filter on, minimize, read wallpaper alpha.

### S2-2 Colour filter: `cogl_framebuffer_set_viewport: assertion 'width > 0 && height > 0'` CRITICALs
- File: features/colorFilters/index.js:121-130 (`_attach` on `child-added`).
- Steps: gs color-filter true, open Spotlight (or Launchpad, QS) -> 5 CRITICALs per new overlay; run C: 0 after enable, 5 after the first Spotlight, 10 after the re-enable (shell.log lines ~94-98). Run B had 9. The new child has size 0x0 when the effect is attached (uiGroup also has 0x0 children: Meta_WindowGroup, modalDialogGroup, screenshotUIGroup, Dummy Cursor).
- Fix: attach lazily (first `notify::mapped` with allocation > 0, or an idle after child-added) and skip hidden or 0x0 children; re-evaluate on `notify::allocation`.

### S2-3 Default menu-bar logo is the generic GNOME foot on real Fedora
- File: features/menuBar/logoMenu.js:104-116, 161-165 (`logoNames` only tries `<LOGO>-symbolic`, then `start-here-symbolic`).
- Evidence: the harness root is Fedora 44 (os-release LOGO=fedora-logo-icon). fedora-logos ships `fedora-logo-icon` only as full-colour PNG (hicolor/*/apps), no `-symbolic`, so every screenshot shows the Adwaita foot (e.g. `c4-qs-light.png` top-left). The "distro logo" is not shown by default; menubar-logo default is 'fedora'.
- Fix: bundle `icons/fedora-logo-symbolic.svg` (and a generic fallback) and pick it when LOGO is fedora-*, or tint the full-colour icon with a ColorizeEffect to the bar's text colour.

### S2-4 Glass drop shadow still ends in a hard edge on bright content (FX6 left it, confirmed and measured)
- File: styles/base.css:45-51 (`.kiwi-glass-shadow` box-shadow 0 12px 28px -12px rgba(0,0,0,.40/.20)).
- Evidence: `b2-qs-sm.png` (dark scheme, white window behind QS): column x=1050, y=443 -> 239, y=446 -> 255: a 16-level step, 28 px below the menu, plus a vertical step at the left (~18 px). `c4-qs-light.png`: 248 -> 255 (7 levels) at y=445. Not visible over dark content (`c4-qs-dark.png`). The edge is St's blur truncation (the gaussian is cut at one blur radius, ~13% of the alpha), not an actor clip.
- Fix: alpha tail under ~5/255 (alpha <= 0.15 for blur 28) or a 9-slice PNG shadow with a zero-alpha border (icons/glass has the assets dir), or two lighter stacked hosts.
