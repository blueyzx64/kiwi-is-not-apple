## Findings for orchestrator
Severity: S1 = crash or data loss, S2 = wrong result or freeze a user will hit, S3 = minor or edge case, S4 = cosmetic.

### S2
1. **The Shell freezes while parsing a large org.gtk.Actions reply.**
   - Where: core/appMenus/gtkActions.js:44-50 (deepUnpack, then recursiveUnpack per action, then parseDescribeAll's sort), all on the main loop.
   - Trigger: an app that exports many actions. Any session app can do this, and it runs on every refocus followed by a menu open.
   - Wrong result: the compositor stalls. Measured max main-loop gaps:
     - 10k actions: 410 ms (run A, r3-big-fetch);
     - 50k actions: 1636 ms for the fetch (run D, r3-huge-fetch);
     - 50k actions, refocus then open a menu: 1361 ms (r3-huge-focus-cost).
   - Confidence: high.
   - Fix:
     - cap the reply: reject a DescribeAll reply over N entries (for example 2000), or call List and Describe only the WELL_KNOWN names (about 40);
     - never deep-unpack state variants, since only a boolean state is used;
     - keep the 2 s timeout.
2. **Menu items show a stale enabled or checked state while the window keeps focus.**
   - Where: core/appMenus/service.js:305-309 (stale is set only on window-focused) and features/menuBar/appMenuBar.js:337 (isStale is false after the first fetch).
   - Trigger: open Edit, change the app's state (Undo becomes enabled), then open Edit again.
   - Wrong result: Undo stays disabled. Run A, r3-stale: `undoBefore=false afterFlip model=false menuSensitive=false appSays=true`.
   - Confidence: high.
   - Fix (either one):
     - mark the entry stale whenever a menu closes, or on every open (the reply is async and cheap once finding 1 is capped);
     - subscribe to org.gtk.Actions `Changed` signals while a menu is open.
3. **A failed or timed-out fetch is cached as a valid empty result.**
   - Where: gtkActions.js:51-55 returns [] on any error, and service.js:227-231 stores it with stale=false.
   - Trigger: the app is busy for more than 2 s when it is focused (startup, a heavy save).
   - Wrong result: generic-only menus (no Edit, no app Quit or Settings) until the user focuses another window and comes back, even after the app recovers. Run A, r3-slow-poison: `titlesAfterAppRecovered=org.r3.Slow,File,Window,Help cachedActions=0`.
   - The Shell itself did not freeze (gap 72 ms).
   - Confidence: high.
   - Fix: let describe() rethrow non-cancel errors, or mark a failed result stale, so the next open re-reads it; optionally retry once with backoff.
4. **Force Quit kills a different app than the one named in its confirmation.**
   - Where: features/menuBar/forceQuit.js:86-90 (select() does not reset or refresh the confirm step) and 238-247.
   - Trigger: click Force Quit on app A (the question names A), click row B (or press Up or Down), then click Force Quit.
   - Wrong result: B is killed without ever being named. Run A, r3-fq-switch: `question=[…force “R3 VA”…] afterClickingB=[true:…“R3 VA”…] VA alive=true VB alive=false`.
   - Confidence: high.
   - Fix: in select(), call _setConfirm(false) when the selection changes, or make rows insensitive while confirming. Also re-check that the selected id equals the id that was confirmed.
5. **F10 (or the Force Quit shortcut path) opens a menu on the hidden bar in full screen.**
   - Where: features/menuBar/index.js:154-166 and appMenuBar.js:217-229; fullscreenReveal.reveal() is never called.
   - Wrong result: the menu floats at the top left with no bar, and the reveal state is not entered. Run B, r3-f10-fullscreen: `menuOpen:true panelVisible:false revealed:false`; shot r3-b2-f10-in-fullscreen.png.
   - Confidence: high.
   - Fix: MenuBar.focus() should call part('fullscreen')?.reveal() first, and conceal when the menu closes (the existing _maybeConceal path).
6. **Keyboard navigation reaches menus the overflow hid, and skips the others.**
   - Where: appMenuBar.js:70-91. OverflowLayout leaves overflowed buttons visible at 0x0, so the panel's menuManager still navigates to them.
   - Trigger: at 1024x768 with a long app name, Edit, Window and Help are hidden.
   - Wrong result: F10 then Right goes App > File > **Help@w0**. Edit and Window are unreachable by keyboard, and the Help menu opens under the notch from a zero-width source. Run E, r3-kbd-hidden-menus; shot r3-e1-hidden-menu-open.png.
   - Confidence: high.
   - Fix (any of these):
     - set container.visible=false (or reactive and can_focus false) on the overflowed buttons after allocation, through a later idle and not in vfunc_allocate;
     - add a "»" overflow menu;
     - shrink the app name with ellipsis instead.

### S3
7. **The wallpaper decode blocks the main loop.**
   - Where: adaptiveBar.js:491-500. GdkPixbuf's stream-at-scale loader decodes on the main thread, even when scaling.
   - Measured on a 9000x6000 PNG: 686 ms for 'centered', 645 ms for 'zoom' (run E, r3-wp-measure-isolated).
   - Context: the Shell's own load of the same file stalls 1970 ms, so this is a one-off per wallpaper and is cached.
   - Fix: decode in a thread (Gio.Subprocess helper, or GdkPixbuf.Pixbuf.new_from_file_at_scale inside a GTask is not available to JS). Simplest: reuse lib/wallpaperTint's sampler, or decode a JPEG or PNG thumbnail from the GNOME thumbnail cache.
8. **Mixed wallpaper band: dark text on a dark scrim over the dark half.**
   - Trigger: left half black, right half white. The result is darkText=true with scrim, and the menus (left) read grey on near-black (run B, r3-b5-split.png).
   - Fix: decide the text from the band under the left (menu) and right (status) zones separately, or make the scrim light when darkText is set.
9. **RTL: OverflowLayout always lays out left to right and ignores the text direction.**
   - Where: appMenuBar.js:70-91. With the panel subtree set to RTL, the app name sits left of File, the overflow clips the wrong end, and the logo and traffic lights are mirrored (run C, r3-c-rtl.png, emulated by set_text_direction because the roots have no RTL locale).
   - Fix: if the actor's text direction is RTL, place from box.x2 leftwards.
10. **Timed XML wallpapers are measured on the first `<file>` only.**
    - Where: lib/wallpaperModel.js:44-51 and adaptiveBar.js:481-487.
    - Fedora's default wallpapers are day/night XML, so at night the bar may use the day image's luminance. Code-level only; the roots ship no backgrounds.
    - Fix: pick the slide for the current time, and resample at the transition.
11. **F10 default is a global Mutter grab.**
    - Where: schema `menubar-focus-shortcut` = ['F10'], lib/keybindings.js:53.
    - It takes F10 away from every app: GTK primary menus, and F10 to quit in mc and htop in terminals. It follows plan §5.1, but it is a regression for terminal users. Code-level.
    - Suggest Ctrl+F2 (the macOS default) or no default.
12. **fullscreenReveal.js:133-142 uses a raw menu.connect that the CleanupRegistry does not track.**
    - Every notify::hover while a menu is open adds another handler, and the handlers outlive a disable.
    - Fix: track one token in the cleanup and replace it.
13. **The expanded notch card (430x116) covers the app name and menu titles at 1024x768** (run C, r3-c-notch-notification.png). It is transient, so this is a design call.
14. **Relaunch can stay armed indefinitely.**
    - Where: forceQuit.js:256-266. If kill() does not stop the app, the notify::state relaunch watcher stays armed, and the next normal quit relaunches the app. Code-level.
15. **Out of scope (dock):** features/dock/view.js:130-131 accesses a disposed St.Widget across enable/disable (runs B and D summaries).

### S4
16. String.replace('%s', x) with names containing `$&` or `$$` mangles labels: logoMenu.js:448 (real name), model.js:183 (app name), forceQuit.js:229. Use a function replacer.
17. About This PC memory uses MemTotal (model.js:186-205): a 16 GB machine with iGPU-reserved memory shows "15 GB". Round up to the nearest standard size.

### Disproved or OK (tested)
- Hung-app Force Quit: Mutter kills the pid (oldPidAlive=false), and Relaunch starts a new instance with a window (run D).
- A never-answering app (busy loop) does not freeze the Shell: 2 s timeout, gap 72 ms.
- Power items go through gnome-session Shutdown(0), Reboot and Logout(0), so the end-session dialog confirms. Sleep is immediate, as on macOS (run F).
- Quick flick at the top edge: no stuck reveal. Disable while revealed: the panel is restored (ty 0, hidden in full screen, track_hover restored).
- Zoom crop luminance matched the real screen pixel (run B, r3-wp-zoom-crop).
- Long window titles are ellipsized; the Window menu stays on screen.
- 6 extension toggles plus part toggles: stage actors 1842 → 1786, menus 16 → 16, tracked chrome 19 → 19, appMenus refs 1, no class leaks.
- Keyboard: F10, then Right and Down, then Escape returns focus to the window. Super+Alt+Esc opens Force Quit, the arrows select, and Esc closes.
- Cancel with Return in the Force Quit confirm: St.Button handles it before the bubble-phase handler (code check).
