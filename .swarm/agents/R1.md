## Findings for orchestrator

### S2
**F1. A Kiwi settings reset while Kiwi owns a key loses the user's value for good.** core/originals.js:282 release(), :214 original.
- Trigger: `gsettings reset-recursively org.gnome.shell.extensions.kiwi`, `dconf reset -f`, or anything else that empties `saved-originals` while a SettingOwner holds a key.
- Wrong result: release() finds no entry and writes nothing. Kiwi's forced value stays for good. Probe P1: button-layout stays 'appmenu:', so the user has no window buttons.
- Mitigation found: prefs "Reset Everything" skips saved-originals.
- Confidence: high.
- Fix: keep the original in memory in the owner (set in _take and _onChanged) and fall back to it. Watch `changed::saved-originals` and write the entry back when it is missing.

**F2. restoreStale() overwrites a change the user made after a crash.** core/originals.js:147-165.
- Trigger: the session crashes, or Kiwi errors, while it owns a key. The user then changes that key (Tweaks) before Kiwi next starts.
- Wrong result: the next enable writes the old original over the user's new choice. Probe P2: 'USER-NEW' becomes the old value.
- Confidence: high.
- Fix: store Kiwi's forced value next to the original, and restore only while live === forced.

**F3. Dash to Dock is switched on and then off at every login.** extension.js:65 with core/originals.js restoreStale and features/dock/dashToDock.js. Proven in the real Shell.
- Trigger: GNOME never calls disable() at logout, so after any session that ended with Kiwi's dock running, `enabled-extensions` lacks Dash to Dock and the store still holds it.
- What happens at the next login:
  1. Kiwi's enable() runs restoreStale, which adds Dash to Dock back.
  2. The Shell enables Dash to Dock: it is not in `_enabledExtensions`, which was computed at load (extensionSystem.js:707).
  3. The dock's idle strip removes it again, and the Shell disables it, rebasing every extension after it.
- Evidence (run1): FAKED2D enable at 09:57:59.855, disable at 09:58:04.314. A real Dash to Dock would show its dock for about 4 s at every login.
- Confidence: high.
- Fix: restoreStale must not undo 'members' entries that a feature will take again. Options:
  - pass restoreStale a predicate (e.g. "registry wants dock"), keep the entry, and let ListMembersOwner._take adopt it;
  - or restore 'members' entries only after the first registry pass has settled, and only those no owner adopted.

**F4. Non-UTF-8 bytes in the user's files are corrupted.** lib/cleanup/fileOps.js:54 (`new TextDecoder()`, non-fatal). Proven in the real Shell.
- Trigger: any invalid UTF-8 byte in a file Kiwi edits.
- Wrong result: the byte is decoded to U+FFFD and written back. Run2: é (0xE9) in the user's own comment in ~/.config/gtk-3.0/gtk.css became EF BF BD, outside Kiwi's block.
- Who writes it: gtkTheme on every enable and disable, and the cleanup. The same applies to userChrome.css and user.js.
- Confidence: high.
- Fix: decode with `{fatal: true}` and leave the file untouched on error (log it), or splice bytes.

### S3
**F5. Registry re-entrancy: a settings write inside enable() starts the same feature twice.** lib/featureRegistry.js:268 _enable, :112 refresh.
- Trigger: a feature's enable() writes a Kiwi key that is not in KEYS_THAT_NEVER_AFFECT_FEATURES.
- Wrong result: the nested pass sees st.active still false and enables the same entry again. The first instance leaks. If every write emits, it recurses until "too much recursion" (R1: 1071 enables, 1070 leaked instances).
- Latent: no feature does this today.
- Fix: a pass-in-progress guard that queues keys, plus a 'starting' state.

**F6. Conflict chains depend on registration order.** featureRegistry.js:146 _effective.
- Trigger: x conflictsWith y, y conflictsWith z, registered in the order z, y, x.
- Wrong result: z is paused although its only winner, y, is paused too (R2).
- Latent: no chains exist today.
- Fix: resolve the entries in winner order, recomputing from the wanted set.

**F7. cleanupModel.stripStaleGtkImports has three faults.**
- (a) The block is dropped whole when no import is left, so user rules inside it go (C1). gtkTheme replaces the block anyway, so this is a policy question.
- (b) :29 `whole.replace(body, str)` reads `$&` and `$'` in a kept path as patterns, which corrupts the file (C2). Use a replacer function.
- (c) :23 decodeURI throws URIError on a stray '%', so the step fails at every start forever (C3). Wrap it in try.

**F8. The gtk-css cleanup step is dead code.** gtk-theme always runs first, and its LEGACY_IMPORT_REGEX plus the block replace already drop the 2.x imports.

**F9. A failing cleanup step is retried at every enable, and the cleanup cannot be cancelled.** lib/cleanup/index.js:103-126.
- A step that fails for good (an unreadable profile; GTK3_MODULES still set in this session's environment) reruns on every unlock and re-reads every profiles.ini.
- There is no Cancellable: writes continue after disable().
- Fix: retry at most once per Shell session (a module-level flag), and pass a Gio.Cancellable.

**F10. A lost end marker deletes user rules.** mozillaModel.js:27 BLOCK_REGEX. With `begin A, user rules, begin B, end`, the user rules between the two begins are removed (C5).

**F11. stripKiwiEnvironment removes the user's own modules.** cleanupModel.js:62 drops the whole GTK3_MODULES line, including the user's other modules, if the user edited Kiwi's line (C4). Fix: remove only the Kiwi path element.

**F12. Unset keys come back as explicit values.** originals.js:238 _take stores the live value, not whether the user had set the key. A default comes back as an explicit user value, so a later GNOME default change no longer applies. Fix: store `user: get_user_value(key) !== null` and call reset() on release; dockColourPlan already does this.

**F13. Two owners of one key leave Kiwi's value behind.** When their lifetimes overlap, the second owner's release restores nothing (P4). The registry's stop-before-start ordering prevents this for button-layout today, but nothing enforces it. Fix: a refcount per id, or an assert.

**F14. One damaged store entry wipes all the others.** originals.js:73 _read. A store whose JSON does not parse is treated as {}, so the next set() drops every other entry (P3). Fix: never write after a parse failure; keep the raw text in a backup key.

**F15. "Reset Everything" causes a refresh storm.** prefs/pages/general.js:46 resets about 200 keys one by one, so the Shell runs a registry pass per key and features stop and start several times. It also resets the deprecated 2.x restore records (saved-button-layout, dock-colors-saved). Fix: settings.delay() and apply(), and skip deprecated keys.

**F16. prefs.js:44-47 adds to the display on every window.** The CSS provider and the icon search path are added on every fillPreferencesWindow and never removed. The Extensions app process reopens prefs windows. Also, Gtk.StyleContext.add_provider_for_display is deprecated since GTK 4.10 (still works on 4.20).

**F17. Window events cost O(n) each, O(n²) at session start.** core/desktop.js:110: tracked-windows-changed resyncs appId for every window. _appIdOf also scans appSystem.get_installed() for window-backed apps.

**F18. Two springs on one property fight.** core/motion.js:147 has no per-(actor, prop) exclusivity, so both write every frame. Seen with the dock bounce firing twice. Fix: keep a WeakMap of actor+prop to the running spring and cancel it.

**F19. extension.enable() is not exception-safe.** A throw after Motion.start() or the settings connect leaves the Shell in ERROR without calling disable(), so everything set up so far leaks. Fix: try/catch with this.disable().

**F20. Stale doc reference.** lib/migrations.js:3 names tests/deprecatedKeys.test.js, which does not exist; the check lives in tests/architecture.test.js.

**F21. One failed restore skips the other.** extension.js:63-66: restoreLegacyButtonLayout and restoreStale share one try, so a throw in the first skips restoreStale.
