## Findings for orchestrator

1. **Input Capture portal: available on F44.**
   - Backend present: `/tmp/x2/f44/usr/share/xdg-desktop-portal/portals/gnome.portal` lists `org.freedesktop.impl.portal.InputCapture`; the backend binary `usr/libexec/xdg-desktop-portal-gnome` implements `XdpImplInputCapture` and proxies `org.gnome.Mutter.InputCapture`.
   - Frontend interface: `usr/share/dbus-1/interfaces/org.freedesktop.portal.InputCapture.xml` (v2): CreateSession2, GetZones, SetPointerBarriers, Enable, Disable, Release, ConnectToEIS; signals Disabled, Activated, Deactivated, ZonesChanged; properties SupportedCapabilities (1 KEYBOARD, 2 POINTER, 4 TOUCHSCREEN), version.
   - What it allows: an app can only ENABLE capture; the compositor decides when to ACTIVATE it (via pointer barriers crossing). No immediate capture. Events are delivered over libei (ConnectToEIS fd), not as D-Bus signals. Capabilities are a subset of what the backend supports; a dialog (`inputcapturedialog.ui`) asks the user for consent.
   - Caveat: the exact keyboard/pointer/touch values GNOME 50 reports come from Mutter at runtime; not checked live.
   - Sources: `xdg-desktop-portal-gnome` 50.0 `src/inputcapture.c` (capabilities bitmask, line ~30-36, ~838-841).

2. **localsearch (Tracker 3): does NOT index `user.xdg.tags`.**
   - No reference to `user.xdg`, `xdg.tags`, `xdg:tags` or `xattr` anywhere in the localsearch 3.11.2 source (depth-1 clone of tag 3.11.2), nor in the installed `usr/libexec/localsearch-3` binary or `usr/lib64/localsearch-3.0/*`.
   - Tags are only handled as `nao:hasTag` (PDF extractor `src/extractor/tracker-extract-pdf.c:369`; XMP/gstreamer writeback). So the xattr tag must be read by something else, or it is not indexed.
   - Endpoints: bus name `org.freedesktop.LocalSearch3` (service file `usr/share/dbus-1/services/org.freedesktop.LocalSearch3.service`; app-id built in `src/indexer/tracker-application.c:1455`). Legacy alias `org.freedesktop.Tracker3.Miner.Files` (also in services dir, `tracker-application.c:1205`).
   - Per-location SPARQL endpoint: object path `/org/freedesktop/LocalSearch3/<encoded-root-path>` (`tracker-application.c:198-199`), interface `org.freedesktop.Tracker3.Endpoint` (methods Query, Serialize, Update, UpdateArray, UpdateBlank, Deserialize; signal GraphUpdated; strings in `usr/lib64/libtracker-sparql-3.0.so.0.1101.0`).
   - Miner control: `/org/freedesktop/Tracker3/Miner/Files` (interface `org.freedesktop.Tracker3.Miner`, see `usr/share/dbus-1/interfaces/org.freedesktop.Tracker3.Miner.xml`).
   - No `tracker3` / `tracker-miners` packages in F44 root; the CLI is `localsearch` (rpm localsearch-3.11.2).

3. **GNOME Clocks: no D-Bus exposure of running timers.**
   - Clocks 50.0 (`src/application.vala`) registers only two D-Bus objects: (a) `org.gnome.Shell.SearchProvider2` at `<app object path>/SearchProvider` (`src/search-provider.vala`), (b) `org.gnome.Shell.ClocksIntegration` at the app object path (`src/world-shell-world-clocks.vala`, exposes only world-clock locations, property `locations` av).
   - Search provider `data/org.gnome.clocks.search-provider.ini.in`: BusName `@appid@` (org.gnome.Clocks), ObjectPath `/org/gnome/clocks@profile@/SearchProvider`. It searches WORLD-CLOCK CITIES only (GWeather), not timers/alarms.
   - Timers: gsettings `org.gnome.clocks timers` (aa{sv}) stores only `duration` and `name` (`src/timer-item.vala:69-73`). Running state is in-memory (`src/timer-face.vala` is_running). Not in gsettings, not on D-Bus.
   - Not installed in `/tmp/x2/f44`; the source check is from gnome-clocks tag 50.0.

4. **Night Light last location: gsettings key `night-light-last-coordinates`.**
   - Schema: `/tmp/x2/f44/usr/share/glib-2.0/schemas/org.gnome.settings-daemon.plugins.color.gschema.xml`. Path `org.gnome.settings-daemon.plugins.color`, type `(dd)`, default `(91,181)` (invalid, forces update at startup), "last detected position" (lat, lon).
   - Related keys in the same schema: `night-light-enabled` (b, false), `night-light-temperature` (u, 2700), `night-light-schedule-automatic` (b, true), `night-light-schedule-from` (d, 20.00), `night-light-schedule-to` (d, 6.00).

5. **GNOME 50 colour filters: no greyscale or colour-blindness keys.**
   - No schema key for colour-blindness or greyscale filters exists in `usr/share/glib-2.0/schemas`.
   - The only colour effects are magnifier-based: `org.gnome.desktop.a11y.magnifier` keys `invert-lightness` (b), `color-saturation` (d, 0.0 greyscale to 1.0 colour), `brightness-red/green/blue`, `contrast-red/green/blue`.
   - UI: control-center's Zoom page (`CcUaZoomPage`) has a "Color Filters" group with "Inverted" and brightness/contrast/saturation rows (strings in `usr/bin/gnome-control-center`).
   - Shell applies them only while the magnifier is on: `js/ui/magnifier.js` (INVERT_LIGHTNESS_KEY, COLOR_SATURATION_KEY, gnome-shell 50.0 source); `js/ui/status/accessibility.js:175` binds `screen-magnifier-enabled` (`org.gnome.desktop.a11y.applications`).
   - Implication for Kiwi: greyscale = magnifier on + color-saturation 0.0; no separate filter toggle exists.
