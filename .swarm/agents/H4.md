### 1. Reduced motion (GNOME 50)
- Schema id: `org.gnome.desktop.a11y.interface`, path `/org/gnome/desktop/a11y/interface/`, key `reduced-motion`.
  - File: /tmp/x2/f44/usr/share/glib-2.0/schemas/org.gnome.desktop.a11y.interface.gschema.xml lines 18-24 (also tag 50.0 gsettings-desktop-schemas `schemas/org.gnome.desktop.a11y.interface.gschema.xml.in` line 18).
- Type: enum `org.gnome.desktop.GDesktopReducedMotion`, default `'no-preference'`.
  - Values: `no-preference` (=0), `reduce` (=1).
  - File: /tmp/x2/f44/usr/share/glib-2.0/schemas/org.gnome.desktop.enums.xml lines 205-208.
- The key is compiled into gschemas.compiled (`(b)reduced-motion` string present).
- Shell 50 does NOT read `reduced-motion`. Its only motion switch is `org.gnome.desktop.interface enable-animations` (bool, default true; .../org.gnome.desktop.interface.gschema.xml lines 11-18), read via St.Settings `enable_animations`. Evidence: js/misc/animationUtils.js lines 23-32 (`adjustAnimationTime`), js/misc/introspect.js line 54. libshell/libst strings contain no "reduced-motion".
- Shell does read `org.gnome.desktop.a11y.interface` for `show-status-shapes` (ui/popupMenu.js 406-413), so a Kiwi consumer must read reduced-motion itself via Gio.Settings and honour both keys.
- Note: I could not fetch the 50.0 enums.xml from GitLab (404 on the path tried). The local enum file is used for the values.

### 2. Notification APIs in GNOME 50 (verified in ui/messageTray.js, ui/messageList.js, ui/notificationDaemon.js)
- There is NO `NotificationGroup` class in 50. Grouping is per Source. One MessageTray.Source per app (FDO: `_getSourceForApp` keyed by app, else by sender/pid; GTK: GtkNotificationDaemonAppSource keyed by appId). Source = `MessageTray.Source` (messageTray.js 507-628) which extends `MessageList.Source` (messageList.js 280-306).
- UI grouping: `NotificationMessageGroup` (messageList.js 872+), created per source in `MessageView._addNotificationSource` (messageList.js 1816-1840). `hasUrgent` = `_nUrgent > 0` (957-959).
- Source API: `source.notifications`, `source.count`, `addNotification(n)` (messageTray.js 579-601), `destroy(reason)`, `policy` (NotificationPolicy with enable, showBanners, enableSound, forceExpanded, showInLockScreen, detailsInLockScreen).
- Source signals (messageTray.js 512-521): `destroy(uint)`, `notification-added(Notification)`, `notification-removed(Notification)`, `notification-request-banner(Notification)`.
- MessageTray (messageTray.js 702-708): signals `queue-changed`, `source-added(Source)`, `source-removed(Source)`; `getSources()` at 893. Also `add(source)` at 860.
- Notification (messageTray.js 355-500): GObject props `source` (construct-only), `title`, `body`, `use-body-markup`, `gicon`, `icon-name`, `sound`, `datetime`, `privacy-scope`, `urgency` (int), `acknowledged`, `resident`, `for-feedback`, `is-transient` (the GJS camelCase accessor is `isTransient`, set at notificationDaemon.js 257-261). Signals: `action-added`, `action-removed`, `activated`, `destroy(uint)`.
  - Actions: `addAction(label, callback)` (431), `removeAction`, `clearActions`, `actions` getter. `Action` class at messageTray.js 337-353 has `label` and `activate()`. Daemon skips the 'default' action id and records it as hasDefaultAction (notificationDaemon.js 218-232).
- Urgency enum (messageTray.js 59-64): `LOW=0, NORMAL=1, HIGH=2, CRITICAL=3`. FDO hints map (notificationDaemon.js 29-33) are its own enum LOW=0, NORMAL=1, CRITICAL=2, mapped into MessageTray.Urgency. GTK priority map `low/normal/high/urgent` -> LOW/NORMAL/HIGH/CRITICAL (notificationDaemon.js 409-412). Critical notifications bypass banner suppression and are auto-expanded (messageTray.js 935-950, 1170-1172).
- Transient: `is-transient` set from FDO hint `transient` (notificationDaemon.js 257-261). Used at messageTray.js 1276 to hide on dismiss.
- Hooks to observe new notifications and grouping:
  - `Main.messageTray.connect('source-added' | 'source-removed', ...)` for new/removed app groups.
  - Per source: `source.connect('notification-added', ...)` and `'notification-removed'`, `'notification-request-banner'`, and `'destroy'`, or `source.connectObject(...)`.
  - Per notification: `'destroy'`, `'action-added'`, `'activated'`, and `notify::urgency`.
  - Global list: `Main.messageTray.getSources()` then each `source.notifications`.
  - Caveat: messageList.js line 956 connects `'notification-added'` on the source, so Shell's own UI uses the same signal.
