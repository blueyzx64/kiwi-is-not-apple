## Findings for orchestrator
- No real bug found; nothing skipped.
- Ambiguity (pinned as documented): windows({minimized: true}) does not filter; only `false` drops minimized windows.
- Ambiguity (not pinned): upsertWindow(id, {appId: undefined}) stores undefined, not the default/old value (`f in fields`). An adapter passing `app?.get_id()` could write undefined instead of null; apps() skips it but windows({appId: null}) will not match it.
- Ambiguity (not pinned): resolve(req, {reducedMotion: true}) without `animations` is treated as animations OFF (duration 0), because the check is `!env.animations`. Callers must pass both fields.
- Note (pinned): focusing a window whose listener closes it in 'window-focused' never emits app-focused for its app (state stays consistent: focus null, app null).
- Note (pinned): springDuration of an undamped spring (damping 0) is ~10 s (search limit), not infinite; custom springs with low damping can produce very long animations.
- Cancellation is not in the pure model (core/motion.js handles it); tests pin purity/repeatability so a cancelled request can be replayed.
