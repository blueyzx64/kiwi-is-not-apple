# Porting matrix: every macOS feature (2018 → 27) mapped to Kiwi

Synthesis of the six research files in this folder. Each macOS feature appears **once**, even when several releases changed it; the Sources column links every section that covers it. Target: GNOME Shell 50, Fedora 44, Wayland. Phases refer to the revised plan in [`overhaul-plan.md` §7](../../architecture/overhaul-plan.md#7-phases-each-ends-merged-to-main-tested-in-the-real-gnome-50-environment).

**How to read it**
- **Phase:** `P0`–`P8` = the overhaul phase that builds it; `have` = Kiwi ships it today (the phase after it is where it gets reworked); `later` = after P8 (the research's "Later (P3)" tier); `skip` = not ported. A `?` marks a row that waits on an owner decision ([conflicts](../../architecture/overhaul-plan.md#11-conflicts-needing-owner-decision)).
- **Mechanism:** `shell` = inside the extension; `companion` = a separate helper or add-on shipped by the installer, never by `enable()`; `GNOME app` = configure or recommend an existing GNOME app; `installer` = the owner's app-installer; `skip`.
- **Effort:** S (days), M (one to two weeks), L (several weeks), XL (out of proportion or a separate project).
- **Source labels:** MC = [Mojave/Catalina](2018-2019-mojave-catalina.md), BM = [Big Sur/Monterey](2020-2021-bigsur-monterey.md), VS = [Ventura/Sonoma](2022-2023-ventura-sonoma.md), ST = [Sequoia/Tahoe/27](2024-now-sequoia-tahoe.md) (F-numbers), UI = [system UI and apps](native-apps-and-system-ui.md), IN = [installer and app lifecycle](installer-and-app-lifecycle.md).
- When two research files gave different tiers for the same feature, the row takes the more specific file's call and the rationale paragraph says so.

### Hard blockers (things Kiwi cannot do, or can do only by a workaround)
1. **Wayland process separation.** The Shell cannot restyle app windows, sidebars, toolbars or CSD shadows, cannot read or write text fields, cannot remap keys per app, and cannot pre-select portal screen-share sources. Coloured traffic lights *inside* app headerbars would need GTK CSS, which the owner dropped.
2. **App menus.** libadwaita apps export no menu bar (only `app.*`/`win.*` actions and hamburger menus). DBusMenu registers by X11 id, so it works only for Xwayland apps. AT-SPI is the only route beyond that, and it flickers.
3. **Mutter.** No public tiling API (Kiwi tiles are plain resizes and Kiwi must own tile groups), no Split View, no per-monitor independent workspaces, full-screen windows don't get their own workspace.
4. **Private Shell internals** Kiwi must wrap and re-check on every GNOME bump: the overview (`OverviewControls`, `WorkspacesView`), `quickSettings._grid`, `MessageTray`, `ScreenshotUI`, `osdWindow.js`, `_bgManagers`/`_backgroundGroup`, the IBus `_panelService`, `UnlockDialog`, `Main.panel._leftBox/_rightBox`, `AppDisplay`.
5. **No real blur** (owner decision). Faux glass needs higher opacity; GNOME 51's Shell-only blur is an optional extra, never a requirement.
6. **Input limits.** No 2-finger edge swipe (2-finger motion is scroll for apps), no Fn/Globe key (firmware), no haptics, no real ⌘ key without keyd/Toshy (root or `input` group).
7. **Session modes.** Lock-screen features need `unlock-dialog`, which changes Kiwi's whole lifecycle; GDM is unreachable from a user extension (system-wide install only).
8. **No platform for widgets or live activities**, and several features need app cooperation (LauncherEntry badges, Background portal, MPRIS, notification urgency).
9. **EGO review rules.** No bundled binaries, no privileged actions, no blocking IO, declared clipboard use, no data to third parties without explicit action, scrutiny of D-Bus APIs, helpers, `unlock-dialog` and Genie shader code. AI features therefore need a separately packaged, opt-in helper.
10. **Apple-only services, proprietary Continuity protocols and copyright** (SF Symbols, sounds, wallpapers, icons): skipped or replaced by original assets.
11. **Fedora 44 packaging.** GNOME Software uses dnf5daemon, not PackageKit; the installer must make dnf5daemon its primary RPM backend.
